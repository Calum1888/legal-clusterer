# Legal Document Clusterer

An unsupervised pipeline for discovering categories in collections of legal contracts. Compares two competing approaches — classical **TF-IDF + LSA** and modern **sentence embeddings** — and uses a local LLM to label and verify the resulting clusters automatically.

Built and benchmarked on the [CUAD v1](https://www.atticusprojectai.org/cuad) corpus (510 commercial contracts, 25 underlying contract types).

---

## Why this project

Law firms, in-house legal teams, and contract analytics platforms routinely face large corpora of unlabelled contracts. Manually triaging them is expensive; supervised classification requires labels that often don't exist. My work experience at A&O Shearman in their data science department inspired this project. This pipeline tackles the problem in three stages:

1. **Group similar contracts** without supervision.
2. **Describe each group** with a short, human-readable label generated by an LLM.
3. **Verify the groupings** by asking the LLM whether the documents in a cluster genuinely belong together — a lightweight self-audit that surfaces bad clusters before a human reviews them.

The same architecture generalises to any document-clustering problem (support tickets, research papers, news articles) by changing the prompt template.

## Methods

### Two clustering backends, one interface

| | `DocumentClusterer` | `EmbeddingClusterer` |
|---|---|---|
| Representation | TF-IDF (1–3 grams) + Truncated SVD (LSA) | Sentence-transformer embeddings (`all-mpnet-base-v2`) |
| Captures | Lexical overlap | Semantic similarity |
| Dim. reduction | TruncatedSVD → L2 normalise | Native dense, L2-normalised on encode |
| Strengths | Fast, no model download, interpretable features | Robust to vocabulary mismatch, fewer/cleaner clusters |
| Failure mode | Over-segments by surface vocabulary | Coarser clusters; can blur sub-types |

Both backends feed into the same downstream stage (`AgglomerativeClustering` with Ward linkage on Euclidean distance), so the pipeline can swap representations without touching the rest of the code.

### LLM-based labelling and self-verification

`LLMEvaluation` wraps a Hugging Face text-generation pipeline (TinyLlama by default, swappable for any decoder-only model) and provides:

- **`llm_label`** — for each cluster, sample N documents, build a prompt with their content excerpts, and ask the model for a short descriptive label.
- **`evaluate_all`** — for each labelled cluster, ask the model whether the documents actually belong together, parse a YES/NO verdict, and return a `passed` flag.

Both methods build all prompts up front and dispatch them through the pipeline in batches with left-padding for decoder-only models — essential for GPU throughput.

---

## Engineering notes

A few decisions worth flagging:

- **Greedy decoding** (`do_sample=False`) for full reproducibility across runs; no seed management needed for the LLM.
- **Single seeded `random.Random` instance** per call instead of reseeding global state inside loops — fixes a subtle bug where every cluster was drawn from the same RNG state.
- **L2-normalised embeddings + Ward linkage** — because cosine and Euclidean are monotonically related on normalised vectors, Ward (which only supports Euclidean) behaves like cosine clustering and avoids the long-chain failure mode of average linkage.
- **Singleton filtering** (`min_cluster_size`) — clusters too small to label meaningfully are skipped before any LLM call.
- **Numpy int normalisation at the source** — cluster labels are cast to Python `int` once in `fit()` instead of scattering `int(label)` calls across the codebase.

## Results on CUAD v1

After tuning on 510 contracts (ground-truth: 25 contract types):

| Pipeline | Clusters | Silhouette | Singletons | Largest cluster |
|---|---|---|---|---|
| TF-IDF + LSA (tuned) | ~40 | 0.36 | 0 | 22 |
| Sentence embeddings | 36 | 0.11 | 0 | 32 |

The embedding pipeline produces fewer, more semantically coherent clusters that align more closely with CUAD's true contract types, despite a lower silhouette score (a known artefact: tighter sub-clusters score higher than broader but more meaningful ones). The TF-IDF pipeline runs ~30× faster end-to-end and remains useful when sub-type granularity matters more than category recovery.

## Repo structure

```
legal_clustering/
├── document_clusterer.py    # TF-IDF + SVD + agglomerative clustering
├── embedding_clusterer.py   # Sentence-transformer + agglomerative clustering
└── llm_evaluation.py        # LLM-based labelling and verification
running_cluster.py           # End-to-end runner script
data/CUADv1.json             # Not checked in — download separately
```

Each class follows the same shape: parameters set in `__init__`, an explicit per-stage method (`embed`, `clusterer`, `llm_label`, etc.), and a top-level `fit` / `evaluate_all` entry point. Public methods are fully docstring'd.

## Installation and usage

### Requirements

- Python 3.10+
- `scikit-learn`, `scipy`, `numpy`
- `sentence-transformers`, `transformers`, `torch`
- `tqdm`

```bash
pip install scikit-learn scipy numpy sentence-transformers transformers torch tqdm
```

A CUDA-enabled GPU is strongly recommended for the LLM stages; everything runs on CPU but slowly.

### Data

Download CUAD v1 from [The Atticus Project](https://www.atticusprojectai.org/cuad) and place `CUADv1.json` under `data/`.

### Running the full pipeline

```bash
python running_cluster.py
```

This will:

1. Load CUAD contracts.
2. Run the TF-IDF clusterer and print diagnostics (silhouette, cluster sizes, singleton count).
3. Run the embedding clusterer for comparison.
4. Generate an LLM label for each cluster.
5. Run LLM-based self-verification and print any failed clusters with reasons.

### Using a single clusterer

```python
from legal_clustering import EmbeddingClusterer

clusterer = EmbeddingClusterer(
    embedding_model="sentence-transformers/all-mpnet-base-v2",
    dist_threshold=1.5,
    linkage="ward",
    metric="euclidean",
    max_chars=2000,
    batch_size=32,
    random_state=42,
)

# documents: dict of {doc_id: raw_text}
results = clusterer.fit(documents)   # {doc_id: cluster_label}
```

### Configuring the LLM evaluator

```python
from legal_clustering import LLMEvaluation

llm_eval = LLMEvaluation(
    llm_model="TinyLlama/TinyLlama-1.1B-Chat-v1.0",
    max_tokens=100,
    token_price=0.0001,
    n_llm_samples=5,
    prompt_type_of_doc="legal contracts",
    seed=42,
    batch_size=4,
    min_cluster_size=2,
    excerpt_chars=2000,
)

labels = llm_eval.llm_label(results, documents)
verdicts = llm_eval.evaluate_all(labels, results, documents)
```

`llm_model` accepts any Hugging Face decoder-only text-generation model. TinyLlama is the default for ease of local use; swap in a 7B+ model (e.g. `meta-llama/Llama-3.1-8B-Instruct`, `Qwen/Qwen2.5-7B-Instruct`) for substantially better label and verdict quality.

## What I'd do next

- Compute external metrics (ARI, AMI, V-measure) against CUAD's ground-truth contract types for a sharper comparison than silhouette.
- Add long-context embeddings (`jinaai/jina-embeddings-v2-base-en`, 8k tokens) — current 2000-char truncation loses material in longer contracts.
- Replace TinyLlama with a 7B-class model and re-measure verdict quality. The current self-verification is a useful skeleton; a stronger judge would make it actionable.
- Cache embeddings to disk so the embedding clusterer doesn't re-encode on every threshold sweep.
